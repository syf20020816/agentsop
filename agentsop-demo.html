痛点

你问它「写完了吗？」
它永远说「写完了，请确认」。

黑盒焦虑

它到底干完没干完

Claude Code / Codex 把一整段生命周期压进一个对话框。没有阶段、没有产物校验，只有一句「Done」。

追问成本高，而且答案不可信。
上下文割裂

看流程  ↔  复制粘贴

你在看板里看节点，再手动复制 Prompt、切到 Agent、粘贴、回车。每一步都在打断心流。

工具越多，切换越贵。
上下文污染

一插话，主流程就乱

长流程里人一介入，原本干净的上下文被讨论、试错、临时问题污染，之后 AI 开始「忘事」。

高级工程师靠开小窗隔离，但 Agent 没有。
一句话

AgentSOP 的主语不是「帮 AI 写代码」，而是主动让 AI 完成阶段，并把状态变成可视化。

核心想法 01

宏观与微观的完美解耦

人类只关心「走到哪一步」，AI 该干哪些脏活累活，交给底层编排。

人 · 管理层 审批、打回、按下空格。看的是阶段，不是代码。 Product / Reviewer
AgentSOP · 宏观 定义 需求 → 编码 → 测试 → 上线 的粗粒度生命周期。人可理解、可审批、可回滚。 SOP 状态机
picop · 微观 把一个阶段内部拆成复杂的思考、查阅、勘测步骤，编排成可复用的 SKILL。 Skill 编排
执行层 · Agent Claude Code / Codex / Harness —— 最强的执行器，不抢它的饭碗。 Executor
为什么好

看板保持极简，底层保持极强。人不会被细节淹没，AI 也不会因为「大阶段」而漏步骤。

默认 Prompt 支持 /

输入 / 列出本机 skill（Codex / Claude / 共享），选中即插入。命令名以目录名为准，展示名不影响调用。

节点是流程的原子

「+」新建节点追加到末尾并补边；「−」删除节点同时清掉相关边，必要时改 entry。删除只改草稿。

与 picop 的接口

默认 Prompt 里写 /your-skill，宏观节点就自动调用微观编排。SOP 管阶段，Skill 管怎么做。

核心想法 03 · 设计构想

/side：给疑问开一间隔音房

主流程继续跑，你在旁边开一个独立上下文问问题。问完就走，不污染主线程。

主流程 · 干净的上下文
需求分析 起草 PRD 实现 上线

Agent 只看到 SOP 写回的 context.md：当前节点、产物、你的决策。没有被临时讨论冲淡。

/side 窗口 · 用完即弃

贴着当前上下文开一个临时沙盒：为什么选 A 不选 B？这个接口谁在用？问完关掉，主流程零感知。

为什么高级

长流程里人一插话，AI 就开始「忘事」。隔离窗口把「探索」和「执行」分开——这正是高级工程师的工作方式。

三条规则

① 只读主上下文，不写回
② 结论要进主流程，必须由你手动带回
③ 关闭即销毁，不留聊天记录负担
